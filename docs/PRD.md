# NavHoard / 集径 - PRD (MVP)

- 日期: 2026-03-07
- 版本: v0.2
- 状态: 草案

## 1. 背景与目标
1. 用户收藏大量链接后很少回看，信息利用率低。
2. 提供一个可收集、可筛选、可再发现的轻量导航收藏页。
3. 同时支持 GitHub Pages 二级路径部署和博客子路由集成。

## 2. 目标用户与使用场景

### 用户画像
1. 高频浏览技术/资讯网站的个人用户。
2. 维护公开导航站的内容策展者。
3. 依赖自动化抓取与整理的开发者。

### 用户故事
- US-1: 作为技术开发者，我想通过关键词快速找到之前收藏过的文章链接，以便减少重复搜索时间。
- US-2: 作为内容策展者，我想按标签筛选特定领域的链接，以便整理主题化的推荐列表。
- US-3: 作为个人用户，我想把感兴趣的链接标记收藏并随时查看，以便区分"已读"和"待读"。
- US-4: 作为开发者，我想让抓取流程自动提交 PR 并校验数据，以便在不手动干预的情况下持续更新内容。

## 3. 产品定位
1. 带自嘲气质的现代化收藏导航站。
2. 前端只读公开数据，用户私有状态本地保存。
3. 自动化持续更新内容，人工审核保证质量。

## 4. MVP 范围

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | 首页卡片流 | 标题、简介、标签、来源、更新时间 |
| P0 | 关键词搜索与标签筛选 | 支持排序（最新/相关） |
| P0 | 数据读取 | 从 `data/index.json` 加载 |
| P0 | 响应式 UI | 移动端/桌面端 |
| P1 | 本地收藏 | localStorage，支持"只看收藏"视图 |
| P1 | 自动化更新流程 | 抓取 -> 去重 -> 生成标签/简介 -> 提 PR |

## 5. 非目标（MVP 不做）
1. 用户账号与云同步。
2. 评论、点赞、社交互动。
3. 后端服务与数据库。
4. 复杂推荐算法。
5. 暗色模式（作为 M2+ 增强考虑）。

## 6. 信息架构
1. `/` 首页（搜索、筛选、列表）。
2. `/#favorites` 本地收藏页（hash 路由）。
3. `/about`（或弹层）收录规则与更新说明。

## 7. 体验与视觉要求
1. 风格现代、轻量、可快速加载。
2. 统一设计 Token（颜色、圆角、阴影、间距），通过 CSS 自定义属性管理。
3. 卡片交互有轻动效（hover/focus/筛选过渡）。
4. 可访问性: 键盘可操作，WCAG 2.1 AA 对比度达标。
5. 空状态设计:
   - 搜索无结果: 显示"未找到匹配内容"并建议清除筛选条件。
   - 数据加载失败: 显示友好错误提示和重试按钮。
   - 收藏为空: 引导用户去首页浏览并收藏。
6. SEO 基础: 静态 `<title>`、`<meta description>`、Open Graph 标签。

## 8. 技术与部署设计

### 技术选型
| 类目 | 选型 | 理由 |
|------|------|------|
| 构建工具 | Vite | 开箱即用、构建快、生态成熟 |
| UI 框架 | Vanilla TS + Lit（Web Components） | 轻量、无运行时依赖、可嵌入博客 |
| CSS | CSS 自定义属性 + 原生 CSS | 零依赖、与 Web Components 天然兼容 |
| 搜索 | MiniSearch | 轻量全文索引，支持模糊匹配，gzip 后 ~6KB |

### 架构
1. 一套核心、两种壳。
2. `core`: 列表渲染、搜索筛选、状态管理。
3. `standalone`: 独立站部署（GitHub Pages）。
4. `adapter`: 博客集成入口，以 Web Component 形式挂载（`<nav-hoard basePath="/nav/">`）。

### 路径与路由
1. 统一 `basePath` 机制，所有资源和数据请求通过 `resolveUrl(basePath, path)` 生成。
2. `basePath` 通过构建时环境变量 `VITE_BASE_PATH` 注入，默认 `'/'`。
3. 默认 hash 路由，避免二级路径 404。

## 9. 数据方案

### 公共数据
- 存储位置: 仓库内 `data/index.json`。
- 当数据量超过 500 条时，按字母分片为 `data/index-{a-z}.json`，首页加载 `data/manifest.json`（含分片索引和条目总数）。

### 私有数据
- 存储位置: `localStorage`，key 前缀 `navhoard:`。
- 存储上限处理: 捕获 `QuotaExceededError`，提示用户清理旧收藏。

### 条目 Schema

```jsonc
{
  "id": "string",          // 必填，URL 的 SHA-256 前 12 位 hex
  "url": "string",         // 必填，规范化后的完整 URL
  "title": "string",       // 必填，最长 120 字符
  "summary": "string",     // 必填，最长 300 字符
  "tags": ["string"],      // 必填，1~5 个标签，每个最长 20 字符
  "source": "string",      // 必填，来源站点域名
  "created_at": "string",  // 必填，ISO 8601 格式
  "updated_at": "string",  // 必填，ISO 8601 格式
  "confidence": 0.0~1.0    // 可选，AI 生成摘要/标签的置信度，默认 1.0（人工审核后）
}
```

### 去重规则
1. URL 规范化: 转小写、去除 trailing slash、去除 `utm_*` / `ref` 等追踪参数、统一 `http` -> `https`。
2. 基于规范化 URL 的 SHA-256 生成 `id`，`id` 相同视为重复。
3. 冲突合并策略: 保留 `updated_at` 更新的条目，合并两者 `tags`（去重后取并集）。

## 10. 自动化更新（copenclaw）

### 抓取配置
- 抓取源由 `data/sources.yaml` 定义，每个源包含 `url`、`selector`（CSS 选择器）、`schedule`（cron 表达式）。
- 默认抓取频率: 每日一次（`0 6 * * *` UTC）。

### 流程
1. 按 `sources.yaml` 定义抓取目标站点内容。
2. 通过 LLM（API 调用）生成标签和简介，记录 `confidence` 值。
3. 执行去重与 JSON Schema 校验。
4. 生成 PR（默认）或自动 commit+push（通过 `AUTO_MERGE=true` 环境变量开启）。
5. CI 校验通过后自动发布 Pages。

### 告警
- 抓取失败或校验失败时，自动创建 GitHub Issue 并打 `bot:alert` 标签。
- 连续 3 次失败暂停该源抓取，并在 Issue 中标注 `bot:paused`。

## 11. 非功能要求

| 指标 | 目标 | 测量方式 |
|------|------|----------|
| LCP | <= 2.5s（4G 网络） | Lighthouse CI |
| 5k 条搜索响应 | < 200ms | 浏览器 Performance API 埋点 |
| JS Bundle 大小 | < 50KB gzip | 构建产物分析 |
| Lighthouse Performance | >= 90 | Lighthouse CI |
| 离线缓存 | 可选增强，通过 Service Worker 缓存静态资源 | 手动验证 |

### 性能策略（5k+ 条记录）
1. 首次加载构建 MiniSearch 索引，后续搜索在内存中完成。
2. 列表渲染采用虚拟滚动（仅渲染视口内卡片 + 上下各 5 条缓冲）。
3. 搜索输入 300ms 防抖，筛选结果使用 `requestAnimationFrame` 批量更新 DOM。

## 12. 验收标准（MVP）

| # | 标准 | 验证方式 |
|---|------|----------|
| 1 | `https://<user>.github.io/<repo>/` 正常访问，资源无 404 | 部署后手动访问 + CI 检查 |
| 2 | 部署到博客子路由（`/nav/`）后，样式与资源路径正常 | 配置 `basePath=/nav/` 后部署验证 |
| 3 | 搜索 5k 条数据，从输入到结果渲染 < 500ms | Performance API 埋点 |
| 4 | 标签筛选、本地收藏可用，刷新后收藏不丢失 | 手动测试 + E2E 测试 |
| 5 | 自动化任务产出 PR，schema 校验可阻断脏数据 | 提交非法数据触发 CI 失败 |
| 6 | 移动端（375px）无水平溢出，桌面端（1440px）布局正常 | Chrome DevTools 响应式模式 |
| 7 | Lighthouse Performance >= 90，Accessibility >= 90 | Lighthouse CI |
