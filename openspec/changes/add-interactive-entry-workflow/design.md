## Context

现有 `navhoard-cli` 已经具备批量抓取、规范化、去重、校验与输出能力，但还没有“单个 URL → 草稿模板 → 用户确认 → 写入”的交互入口。与此同时，产品侧已经明确这条能力不应被做成另一套独立逻辑，而应作为现有内容流水线的另一种入口与使用方式。

当前最大的实现风险不是 Skill 本身，而是底层写入路径和职责边界尚未完全收敛：PRD 中将 `data/index.json` 描述为主数据源，而当前工具默认写入 `public/data/index.json`。如果不先统一这层抽象，后续 Skill、CLI 和验证流程都会出现重复实现或双写歧义。

## Goals / Non-Goals

**Goals:**
- 增加一个可在会话中触发的单链接录入工作流。
- 让单链接录入与批量更新复用同一套抓取、抽取、规范化、去重、校验和写入逻辑。
- 提供统一的成功 / 部分成功 / 失败模板，保证任何抓取结果都能进入人工确认环节。
- 在条目成功写入后，给出本地验证与后续仓库操作的明确下一步提示。

**Non-Goals:**
- 本次不实现独立 GUI 表单页面；交互以 Agent 会话为主。
- 本次不强制接入真实在线 LLM；若未配置则保持规则法回退。
- 本次不直接扩展为自动 push 工作流；仓库提交相关能力先以检查和引导为主。

## Decisions

### 1. 先做共享 pipeline，再做 Skill 编排
- 第一阶段先补齐可复用的单条内容处理能力。
- 第二阶段再把该能力包装成 NavHoard 专属 Skill。
- 原因：Skill 是交互层，不应成为业务规则的唯一承载位置。

### 2. 先统一 canonical data path，再扩展写入入口
- 必须先明确哪一个文件是内容维护的单一事实来源，并围绕它封装共享读写逻辑。
- 批量更新与单条录入都通过同一抽象完成读取、合并、校验和写入。
- 原因：避免 `data/` 与 `public/data/` 的双写歧义继续扩散。

### 3. 单链接录入拆成两个底层动作
- `captureDraft(url)`: 输入 URL，返回结构化草稿或结构化失败结果。
- `confirmAndWriteEntry(entry)`: 输入用户确认后的条目，执行规范化、去重、校验与写入。
- 原因：这两个动作天然对应 Skill 中“预览”和“确认”两个阶段，也便于 CLI 复用。

### 4. Review template 使用固定字段格式
- 无论抓取成功、部分成功还是失败，都输出固定字段集合：URL、标题、摘要、标签、来源、状态、备注。
- 用户在这个模板上修改，Agent 再解析回结构化数据。
- 原因：比自由描述更容易让用户编辑，也更利于 Agent 稳定解析。

### 5. 仓库操作与 LLM 检查后置为增强项
- 写入成功后，先返回明确的本地验证建议。
- git identity、remote、认证能力以及 LLM 配置等检查，放到后续增强阶段处理。
- 原因：让首版实现先闭合“输入 URL → 确认写入”的核心价值链路，降低首轮复杂度。

## Phased Approach

### Phase 1: Canonical Data Path
- 明确主数据源与发布数据之间的关系。
- 提取共享读写帮助函数，为批量更新和单条写入提供统一入口。
- 验证前端仍能从既定发布路径正确读取数据。

### Phase 2: Shared Single-Entry Pipeline
- 从现有内容流水线中抽出单条 URL 抓取和草稿生成逻辑。
- 定义成功 / 失败结构化返回值。
- 增加确认写入路径，并复用去重与 schema 校验逻辑。

### Phase 3: Interactive Review Template
- 设计一套固定 review template。
- 支持把用户修改后的模板解析回条目对象。
- 写入前必须要求显式确认。

### Phase 4: Skill Workflow
- 创建 NavHoard entry-add Skill。
- Skill 负责引导 URL 输入、展示草稿模板、收集修改结果、确认写入。
- 写入后返回本地验证建议。

### Phase 5: Follow-Up Enhancements
- 增加 git 配置检查与仓库提交引导。
- 增加 LLM 配置检测与规则法回退提示。
- 再决定是否为仓库提交加入实际执行路径。

## Risks / Trade-offs

- [canonical source 未先收敛] → 先完成 Phase 1，再进入 Skill 和单条写入实现。
- [页面抓取质量不稳定] → 用统一失败模板兜底，允许用户手动补录。
- [用户自由修改模板导致解析不稳] → 使用固定字段模板，并对缺失字段给出补填提示。
- [首版范围过大] → 将仓库提交和 LLM 配置检查明确后置，优先闭合最小可用链路。
